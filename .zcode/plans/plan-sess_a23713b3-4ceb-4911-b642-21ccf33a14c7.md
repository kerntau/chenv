## 项目审计结论

Rsbuild + React 19 + wouter SPA，纯本地内容（md require.context 内联 + JSON）。刚经历过一轮清理（c100c1c），基线干净：无调试 console、无注释死代码、devDeps 全部在用、数据访问单一入口 `src/content/index.ts`、日期格式化已统一在 `lib/date.ts`。本轮清理聚焦以下确认属实的问题（均有 grep 引用证据）。

## 一、删除文件

1. `public/og-image.jpg` — 全库零引用（无 og:image meta）。
2. `public/logo.png` — 仅被 `site.config.json` 的 `logo` 字段引用，而该字段无任何代码消费（favicon 用 favicon.svg）。
3. `src/lib/utils.ts` — 仅含 `cn()`，全库只有 Container.tsx 一处调用且为静态类名；删除后 Container 直接写字符串。连带从 package.json 移除 **clsx** 和 **tailwind-merge** 两个依赖。
4. `src/types/env.d.ts` 保留（声明了 `*.md` 模块类型，必需）。

## 二、数据源统一（单一来源 site.config.json）

1. **App.tsx 标题硬编码**：8 处 `'序栈'` → 改用 `siteConfig.title`；同时把「路由前缀 → 中文栏目名」收敛为一个单一映射表，`<Route>` 别名表与 title 逻辑共用同一份路由定义（消除两份手写副本，保留 /article、/timeline 等别名路由不动）。
2. **InneiHero.tsx 社交链接硬编码**（bilibili/x URL 写死）+ **Footer.tsx 三处回退硬编码**（`|| 'https://github.com/kerntau'`、`|| 'hi@keru.in'`）：改从 siteConfig 读取。做法：`site.config.json` 的 `author.socials`（当前无人消费）改造为实际数据源，包含 icon 标识 → InneiHero/Footer 共用同一份社交数据（icon 名映射到 `ui/Icons.tsx` 的组件）。URL 全库唯一来源。
3. **Footer ICP 回退值**与配置值相同 → 直接读配置，删除重复常量。
4. **PostDetail.tsx 分类默认封面表**：保留（仅此一处，非重复），但随封面字段统一一并简化。

## 三、删除无用代码/配置字段

1. `content/index.ts` 的 `getSiteConfig()` — 死导出，删除。
2. `site.config.json` 删除无人消费的字段：`logo`、`favicon`、`seo.keywords`；`SiteConfig` 类型同步收窄。
3. **Post 封面字段三重冗余**（`coverImage`/`cover`/`images` 三字段存同一个值，PostCard.tsx:12 与 PostDetail.tsx:79-81 各自再解析一遍回退链）：`Post` 模型只保留 `coverImage` 一个字段（markdown.ts 解析时仍兼容读取 frontmatter 的 cover/coverImage/images，**不改任何 md 文章**），PostCard/PostDetail 直接用 `post.coverImage`，删除两处重复回退链。
4. `Post.id` 与 `slug` 恒等（markdown.ts:69 `id: finalSlug`）+ `getPostBySlug`/`getDiaryBySlug` 中的 frontmatter.url/id 兼容回退：`id` 与 `slug` 统一为 `slug`，简化 getPostBySlug（postsMap 直接命中即可，无需回退全表扫描——检查所有 md frontmatter 无 url 字段后确认）。
5. **`/feed` RSS 死链**：InneiHero.tsx:23 与 Footer 的「RSS 订阅」指向 `/feed`，该路由不存在（落入 NotFound）。删除这两处 RSS 链接（若你有独立 feed 页面请告知，改为保留）。

## 四、合并重复逻辑

1. `Posts.tsx:86`、`Archives.tsx:75` 手写年份分组 `new Date(date).getFullYear().toString()` → 复用 `lib/date.ts` 的 `getYear()`。
2. `lib/markdown.ts` 的 `parseMarkdownFile`/`parseDiaryFile` 重复的 readingTime/toc/summary 逻辑保持现状（差异真实存在，强行合并反而复杂）。

## 五、依赖与配置

- package.json 移除 `clsx`、`tailwind-merge`（唯一消费者 lib/utils.ts 被删）。
- 其余依赖逐一核实均在用（abcjs/mermaid 动态 import、buffer 为 gray-matter 浏览器 polyfill），不动。
- 配置文件（rsbuild/tsconfig/tailwind/postcss）无冗余，不动。不升级任何依赖。
